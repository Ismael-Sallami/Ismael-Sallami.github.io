Draws an air route over a world map: the flag of every country it visits, and a plane turned
towards the next leg.

Context

Final assignment of Estructura de Datos, year 2 of the double degree in Computer Science
and Business Administration, University of Granada (2023-24).

The problem

Given a file of countries with their coordinates and flag, a store of routes, a world map
and a plane image, produce the map with one route drawn on it. Two things make it more than
a drawing exercise:

  • The map is a PPM image of three million pixels, and the flags and the plane are pasted on
    it with a mask, so transparency has to be handled by hand.
  • The plane has to point along the route, which means rotating an image by an arbitrary
    angle and pasting the result without leaving holes.

The assignment also fixes the design: each type has to expose iterators of its own, so the
structures can be traversed without knowing what is inside them.

The solution

Five types, each with the container that fits its access pattern:

Type Holds Representation Why
Punto A latitude and a longitude Two doubles The leaf of everything else
Pais A point, a name and a flag Value type Ordered by name, so it can live in a set
Paises Every country set<Pais> Lookup in logarithmic time, and no duplicates by construction
Ruta The points of one route list<Punto> Routes are traversed in order and built by appending
Almacen_Rutas Every route by code map<string,Ruta> The program asks for a route by its code, R1 to R5

Each of them ships its own iterator and const_iterator, wrapping the iterator of the
underlying container. That is the point of the exercise: the caller walks a Paises without
learning that a set is inside, and the representation could change without touching a
single loop.

Imagen is the other half: a matrix of Pixel with reading and writing of PPM and PGM,
pasting with a mask, and rotation by interpolation.

Layout

include/          the five types plus the image class
src/              their implementation, the main program and two test programs
data/             countries, routes, world maps, flags and planes
docs/doxygen/     Doxygen main page and the images of this README

Requirements

  • CMake 3.16 or later and a compiler with C++14.
  • Doxygen, only to generate the documentation.

Build and run

cmake -S . -B build
cmake --build build -j"$(nproc)"

./build/ruta_aerea data/paises.txt data/images/mapas/mapa1.ppm data/images/banderas/ \
  data/almacen_rutas.txt data/images/aviones/avion1.ppm data/images/aviones/mascara_avion1.pgm

It lists the routes it has read and asks for a code (R1 to R5). It writes <code>.ppm
in the current directory.

The flags directory must end in a slash: the program concatenates it with the file name.
Two smaller programs, pruebarotacion and pruebapegado, exercise the rotation and the
masked pasting on their own.

If Doxygen is installed, the documentation is generated in
build/doc_doxygen/html/index.html.

Results

Route R1 over mapa1.ppm produces a 3.5 MB PPM image, the one at the top of this README.
The CI draws that route on every push and checks that the output is a valid PPM, so the
example here is verified rather than promised.

What I learned

  • Choosing the container is a design decision, not a detail. set for the countries and
    map for the routes came from how each one is queried, and writing the iterators by hand
    is what showed why the standard library separates iterator from const_iterator.
  • Pasting with a mask and rotating by interpolation are two lines of maths and a lot of
    boundary cases: the pixel that falls outside, the one that falls between four, the one the
    mask leaves out.
  • Limitations, kept as handed in:
    • The program writes its output in the current directory, with no option to choose the
      path, and overwrites without asking.
    • The flags path has to end in a slash, and that is not validated: passing it without one
      produces a file-not-found for every flag.
    • Identifiers, comments and Doxygen documentation are in Spanish.
    • The assignment statement and the presentation written by the teaching staff are not
      published here.
