My Arch Linux desktop: Hyprland on Wayland, Waybar, kitty, and the handful of shell scripts
that put battery, brightness and volume into notifications.

Context

A daily-driver laptop setup, kept in git so a reinstall is an afternoon and not a weekend.
It is a personal repository, not a distribution: it is here to be read and borrowed from,
and to survive my next reinstall.

The problem

A desktop built this way is thirty small files that only make sense together, and they rot
in two ways. They drift, because the copy that runs is not the copy that is stored. And they
stop being portable, because absolute paths creep in: this repository shipped for two years
with notification icons pointing at /home/jose, inherited from someone else's dotfiles.
Nothing failed, the notifications just came up with no icon.

The solution

The tree mirrors ~/.config, and installs as symlinks. Everything under config/ maps
one to one, so the configuration that runs is the file in the repository. Edit one and you
have edited the other; there is no copying step to forget.

No absolute paths. Every reference goes through $HOME, so the setup works for anyone
who clones it. tools/check.sh greps for /home/<user> and fails if one comes back, which
is the only way that class of bug does not return quietly.

Other people's work is not vendored. The repository used to carry copies of
/usr/share/zsh and /usr/share/sddm — 1,872 files and 111 MB, of which about fifty were
mine — plus the same sddm theme three times over. All of that is a pacman command away and
is now written down in docs/install.md instead.

What the CI can check, it checks. No runner starts Hyprland, but shellcheck reads every
script, the waybar configuration is parsed as JSONC, and the portability grep runs. Hence the
checks badge rather than tests.

Layout

config/hypr/         Hyprland: monitors, keybindings, workspaces
config/waybar/       three bars, their styles and their scripts
config/kitty/        the terminal and its colour themes
config/scripts/      battery, brightness, volume, screenshots, lock, and the icons
config/rofi/         config.rasi. The launchers are third-party, see docs/install.md
config/ranger/       the file manager, as ranger --copy-config writes it
config/nvim/         the LazyVim starter, with the plugin versions pinned
config/waypaper/     wallpaper picker
config/lazygit/      git TUI
config/wallpapers/   the wallpaper the compositor and the lock screen use
grub/default         goes to /etc/default/grub
docs/install.md      packages, symlinks and the themes that are not here
tools/check.sh       what the CI runs

Requirements

  • Arch Linux with Wayland
  • hyprland, waybar, kitty, wofi, rofi-wayland, ranger, dunst, waypaper
  • For the scripts: pamixer, light, acpi, playerctl, brightnessctl, swaylock,
    swayidle, xautolock, grim, slurp, libcanberra

The full list, with what each package is for, is in docs/install.md.

Build and run

git clone https://github.com/Ismael-Sallami/Arch_Configuration.git
cd Arch_Configuration

# back up what you have, then link config/* into ~/.config
for d in config/*/; do
  name=$(basename "$d")
  [ -e "$HOME/.config/$name" ] && mv "$HOME/.config/$name" "$HOME/.config/$name.bak"
  ln -s "$PWD/$d" "$HOME/.config/$name"
done

Log out and pick Hyprland. Running the checks:

bash tools/check.sh

What I learned

  • A dotfiles repository is worth exactly what it can rebuild. Everything it points at and
    does not carry — a wallpaper in ~/Imágenes, a theme installed by hand — is a step you
    will have forgotten by the next reinstall.
  • Copying a folder out of /usr/share feels like backing it up and is only weight. The
    package manager already has it, and better versioned than you do.
  • The bugs that survive longest are the ones that fail silently. dunstify -i with a path
    that does not exist shows the notification without an icon and returns success, which is
    why /home/jose lasted two years.
  • Limitations:
    • config/nvim/ and config/ranger/ are the upstream starters with nothing customised.
      They are here so a fresh machine matches, not because there is anything to read in them.
    • The monitor layout is a laptop's: eDP-1 at 1920x1080. An external screen needs the
      monitor= line changed.
    • Comments in the configuration files are in Spanish.
    • The CI checks syntax and portability. Whether the desktop actually comes up is something
      only the machine can answer.
